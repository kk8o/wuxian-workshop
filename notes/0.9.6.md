## 无限工坊 0.9.6

无限工坊：用 AI 写魔兽插件。这一版让插件能直接和 Agent 对话，并把游戏和程序之间的双向通道重新打磨了一遍：更稳、更快、更省。

- 新：插件和 Agent 对话。插件用 `WoWBridge.Bind(插件名)` 拿到句柄：
  - `Emit(主题, 数据)` 把发生的事作为数据发给 Agent，代替 print 调试，Agent 用 `events` 读或等；
  - `Expose(名字, 函数, 说明)` 公开一个函数，Agent 用 `call` 带 JSON 参数调用；
  - `Request(主题, 数据, 回调)` 向 Agent 提问，Agent 用 `respond` 回答；
  - `addon_api` 列出插件公开了什么。

  新建插件的模板已经带好句柄；没装无限工坊的玩家那边，这些调用什么也不做。
- 更省：程序回给游戏的确认改成攒着发，信箱槽位用得少多了。插件一直在刷 print 或发事件时，原来一小时左右就会用光一局游戏的槽位（之后 Agent 发的代码都进不了游戏），现在能撑十个小时以上；空闲心跳从 15 秒放宽到 30 秒。App 概览的「约够多少小时」按最近的实际用量估算。
- 更快：一下子出来很多条小消息（一串报错、刷屏的 print、插件事件）时，几条合成一帧发出，突发时快好几倍。Agent 运行代码的结果插队优先，不再排在一堆报错后面等好几秒。每帧停留时间从 0.25 秒缩到 0.2 秒。
- 更稳：
  - 游戏里登录前就积压了十几条报错时，链路不会再一直连不上。
  - 丢了一帧，程序马上要回来，不再干等 4 秒以上。
  - 发给游戏的代码等不到结果、超时了，没发出去的部分会收回，不会过后（甚至下次开游戏时）突然执行。
  - 重载界面后，之前跑过的代码不会再跑一遍；在信箱里放了很久的旧代码和旧的重载请求也不再执行。
  - 返回值里有秘密值、或者转成文字时出错的值，结果也照常带回来。
  - try 会等游戏把动作之前的输出都送到再汇总，不再漏报。
  - 游戏没开、在读条或信箱用完时，run / load 会马上说明原因，不再干等到超时。
  - 游戏传来的异常数据不会再让日志和事件接口出错；带 `[[` 的参数可以正常传进去。
- 这次更新后，开发组件会更新到 0.9.6（游戏关着时自动装好）。这一版的开发组件有新文件，装好后要完整重启游戏，只重载界面不够。
