## 无限工坊 0.10.0

这一版配合扩展框架 0.7.0：链路跟着应用走，本机扩展的程序可以自己运行应用并把进度报给游戏。需要把游戏里的扩展框架更新到 0.7.0；更早的版本，无限工坊不向它声明应用、不发名单、不发上报，并在「扩展」页提示更新。

- 链路两档：
  - 设置里的「链路」是两档：自动（默认）、常开。以前存下的「按需」读成自动。
  - 自动：声明了 `link: "live"` 的应用（语音搭子这类要即时反应的）运行时，链路一直连着；它停了、游戏退出了，回到传完就收。
  - 常开：游戏进入世界就一直连着。
  - 概览里能看到链路由哪个应用保持，例如「常开 · 由 语音搭子 保持」。
- 本机扩展的程序运行应用：
  - 清单里应用写 `"driver": "local"`，Python 扩展用 `@ext.app("<应用>")` 登记接唤醒的函数，别的不用写：这样的扩展随无限工坊启动，自动要求扩展框架 0.7.0。`start` 写 `"use"`、应用写 `minutes` 会报错。
  - 应用由无限工坊开着：扩展在运行、游戏在线时，工坊声明、打开应用，发心跳，把唤醒一个接一个交给程序（上一个处理完才发下一个）。每次打开先来一个 `open`；掉线、重载、重启后漏掉的条目以 `catchup` 补上。处理到哪由工坊记着。
  - 玩家在卡片上停止后，应用保持停止，直到玩家点「开始」或下次登录、重载。别的原因结束的，5 秒后重新打开。扩展进程停了，应用随之停止。
  - 程序登记的应用与清单里 `driver: "local"` 的应用必须一致，否则扩展不启动，状态里写明缺哪个。
- 上报：`ext.report(应用, key, state, step=, text=, done=, total=, retry=, data=)` 把一件事的进度报给游戏，应用卡片显示最新一条的文字，扩展的游戏插件用 `ext:OnReport` 收。同 key 的新上报替换旧的。游戏不在时工坊按 key 留最新的（每个应用最多 16 个），游戏回来后补送并标 `late`。
- `/wk` 的扩展页：
  - 本机端的运行状态随名单同步：进程启动、停止时立即更新。
  - 本机选项（开关、数字、选择）可以在游戏里改，文字项仍在 App 里改。工坊不接受的值，界面立即回到原值。
- 反射按活跃度：反射新字段 `activity`（`quiet` / `normal` / `lively` 或列表），只在应用当前的活跃度（少说 / 多说）在列表里时触发。清单里应用自己的反射和 `reaction_set` 都能用（后者要写 `owner`）；应用要声明 `pace` 才有活跃度。
- 清单的控件可以带参数：`{"cmd": "mute", "call": "mute", "args": {"on": true}}`，玩家按下时工坊以 `args` 调这个能力。
- 同名插件的替换：
  - 游戏里已有手动安装的同一个插件：批准扩展时换成扩展带的版本，原版本存入历史，可在开发台恢复。游戏里的版本更新时保留游戏中的版本。
  - 批准前的摘要列出将被替换的文件夹和版本（`replaces`）；游戏里的版本在批准前变了，需要重新确认。
  - 不是同一个插件的同名文件夹，在「扩展」页确认后替换。命令行：`wuxian ext install <id> --replace [文件夹 ...]`（不写文件夹名：只换同一个插件的）。
- 调用取回大块数据：调用插件公开的函数，回答最多 16 MB。`wuxian call ... --most <字节数>` 设上限（HTTP `POST /api/call` 的 `most`；SDK `Client.call(..., most=)`）；MCP 的 `call` 工具和 `wk_` 工具固定 256 KB。`timeout_ms` 只管第一段，之后按多久没有新段判断。
- 长回答的进度：`handle:OnProgress(名字, fn)`，回答要分段时开始调一次、每确认一段调一次；`info` 有 `id`、`sent`、`size`、`seconds`，`sent` 等于 `size` 即传完。
- 更新后游戏还没重启时，调用失败的提示会写明游戏里的 WoWBridge 版本，并说明重启游戏后生效。
- App 的「扩展」页：
  - 按钮点不了时，旁边写原因，例如「正在读取摘要」「语音搭子 正在检查」。
  - 修复：从链接打开扩展页，或一个扩展的操作还没结束就切到另一个扩展时，「批准」一直点不了。
  - 「替换游戏插件」只在一处：同一个插件一点就换，原版本存入历史；不是同一个插件先确认。批准卡片列出批准后替换的游戏插件。
  - 安装或批准后需要重启游戏时，写「重启游戏后生效」。
  - 扩展装在电脑上的那一半统一叫「本机端」。
- `wuxian listen` 与 SDK 的应用流：链路待命时心跳放宽，只在租约快用完时才发（租约 600 秒时约每 400 秒一次）；链路连着时每 max(30, 租约 / 3) 秒一次。

给扩展作者：

- 扩展进程协议升到 2：`initialize` 的回答加 `apps`，新增请求 `wake`、通知 `report`。随无限工坊提供的 Python SDK 已是协议 2，用它写的扩展不用改；自己实现协议的扩展见 `guide {"topic": "local-extension"}` 的协议一节。
- 应用声明的 `link` 只有 `"live"` 一个值，不需要即时连接就不写。
- 本机接口：`POST /api/local/install` 的 `replace` 是清单 `[{folder, there}]`，只换清单里、且版本仍是 `there` 的文件夹；`/api/status` 的 `link.held_by` 是 `[{id, title}]`，扩展框架过旧时 `kit.outdated` 为 `{needs, has}`。
