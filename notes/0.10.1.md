## 无限工坊 0.10.1

这一版配合扩展框架 0.10.0。版本是否匹配由无限工坊统一检查：哪里不匹配、先更新什么，App、游戏和 Agent 看到的是同一个结论。版本号从这一版起按「代」编排：无限工坊、WoWBridge、扩展框架的第二位相同（0.10），三者之间有不兼容的改动才一起进 0.11。

- 版本检查：
  - 「概览」和「扩展」页顶部的版本条写需要处理的那一项和办法：更新无限工坊、更新扩展框架或扩展、完整重启游戏、在 Agent 中重启会话；还有别的写「另有 N 项」，能更新的可以「全部更新」。
  - 扩展的标记与状态按同一个检查，例如「需要扩展框架 0.10.0 以上」「已安装 0.10.0，游戏中仍是 0.7.0」「扩展版本过旧：按扩展框架 0.5.0 制作，当前框架支持 0.6.0 及以上的扩展」。
  - 安装扩展前检查版本：需要更新的无限工坊时不安装；只是扩展框架太旧时也不安装，提示先更新扩展框架。
- 链路自己接回：
  - App 窗口从最小化还原，或游戏画面里的帧码被遮挡后重新露出，待命的链路立即接回；常开模式立即开会话，不等 60 秒的重试。
  - 语音搭子这类保持链路的应用，游戏重启后 15 分钟内继续保持。
  - 游戏连续没有应答时，面板显示「待命 · 游戏没有应答」；信件用完时显示「信件用完」和办法。
  - WoWBridge 等待 App 的间隔最长 5 分钟（原 10 分钟）；待命 21 分钟没有收到消息时主动报到。
- 调用插件公开的函数失败时，游戏里的提示写函数名和原因（「X 未完成：原因」），不再当作 Agent 的代码出错。
- 修复：英文 Windows 上，游戏面板里中文的应用名和概览行显示错乱。

给扩展作者：

- 在插件的 `.toc` 写最低版本：`## X-Wuxian-Requires: workshop 0.10.0, WuxianKit 0.10.0`（逗号分开，每项「名称 版本」；名称是 `workshop` 或插件文件夹名）。只管版本，必须在的插件仍写 `## Dependencies`。扩展框架不加载要求不满足的按需加载扩展，`/wk` 写明需要什么；扩展目录的 `needs`、`min_app` 由打包工具从这一行生成。
- 扩展框架的 `.toc` 写 `## X-WuxianKit-Floor`（0.10.0 是 0.6.0）：按更早的扩展框架制作的扩展视为过旧，同样不加载。扩展按哪个版本制作，看它 `X-Wuxian-Requires` 里的 `WuxianKit` 一项，没写的按 0.7.0 算，请写上。
- 不是按需加载的扩展由游戏自己加载，扩展框架拦不住：它照常运行、能力照常可用，`/wk` 和小地图插件列表里多一行提醒；`kit.extensions` 与清单的这一行带 `gate`（`outdated` / `too_old`）。
- 本机扩展清单的 `requires` 参与同样的检查，按它和插件 `.toc` 里较旧的一个算；不满足时 App 提示，但照常载入，方便开发。
- 新建的扩展（`new_extension`）默认写上 `X-Wuxian-Requires: WuxianKit 0.10.0` 和 `requires.kit` 0.10.0。
- MCP `status` 与 `/api/status` 新增 `versions`：`next` 是下一步（`severity`、`action`、`id`、`text`），`items` 是每一项的状态。版本相关的报错（`addon_outdated`、`needs_app`、`needs_kit`、`requires_unmet`）以同一句说明结尾。
