## 无限工坊 0.10.2

这一版配合扩展框架 0.10.1，修正 0.10.1 版本检查的几处遗漏：只通过 MCP 接入的 Agent 也能看到扩展更新，Agent 会告诉玩家该点哪里并等玩家点完，各处提示写清楚原因和办法。

- 扩展更新不必先打开「扩展」页：App 启动时读取上次保存的扩展目录，之后在后台定时检查。只通过 MCP 接入的 Agent 查询状态时也能看到扩展框架和扩展的新版本。
- Agent 告诉玩家该点哪里，并等待玩家完成：
  - 版本检查的每一项都附带处理办法。无限工坊自己的更新写明在「设置 > 关于与更新」里点哪个按钮（「下载」「重启并更新」「检查更新」），不能自动更新的副本写明到官网下载。
  - Agent 把这句话转告玩家后，用新的 `versions_wait` 等待玩家操作完成；App 为更新而重启时，Agent 继续等待。
  - Agent 能列出扩展目录（新的 `extensions`）：可以添加哪些扩展、哪些已有新版本、哪些暂时装不上以及原因。安装和更新仍由玩家在「扩展」页或「概览」的「全部更新」中完成。
  - Agent 不会运行 `wuxian update apply`，也不会替玩家安装或更新。
- 提示更清楚：
  - 本机扩展的游戏部分因版本不符而未被扩展框架加载时，「扩展」页显示「版本不符」并说明需要更新什么，不再提示重启游戏；等待玩家操作时不再一直等下去。
  - Agent 读到的扩展说明区分「已关闭」「版本不符」「在插件列表中被禁用」「无法加载」，分别说明办法。
  - 自检结果的每个修复动作写明由谁、在哪里修复（「自检与修复」页的「修复」，或 Agent 的 `install`）。
- Agent 用起来更顺手（这一版用较弱的模型把全部 MCP 工具逐项试过一遍，按它卡住的地方修改）：
  - 本机扩展指南（`extension_guide`）先给开头和目录，再按章节读取，不再一次返回 55 KB 的全文。
  - API 搜索在同样匹配时先列函数，结果写明手册对应的客户端版本和游戏内实扫日期。
  - 查本客户端已经没有的旧全局函数（如 `IsAddOnLoaded`、`GetItemInfo`）时，`api_get` 写明它不存在、该用哪个 `C_` 函数；控件继承来的方法（如 `Frame:SetPoint`）也查得到，并说明定义在哪个类型上。
  - `api_manual {"topic": "changes"}` 列出最近几次客户端更新新增、改动和删除的 API。
  - 「能不能做」的判断：指南要求先拆分需要的部分、逐项查手册（受保护、机密值、本客户端用 GameRules 关掉的系统），游戏没开时明确说明结论只来自手册，并给出进游戏后用来确认的那条命令。
  - 游戏没开时，报错写明是哪个请求没送到；说明里写明此时没有 `wk_` 工具。
  - 静态检查：有条件保护的旧全局函数，提示里写明只是警告的原因。
- 修复：没有游戏部分的本机扩展不再按扩展框架的最低制作版本判断为过旧。
- 修复：第一次启动、还没有保存过扩展目录时，立即读取扩展目录，不再等 10 秒。
- 修复：本机扩展的游戏插件在插件列表里被禁用时，游戏里不再反复弹出「kit.app.declare 未完成」；扩展框架的应用卡片写明「游戏插件已在插件列表中禁用」。
- 修复：热加载带有全局名称的窗口（如 `CreateFrame("Frame", "MyFrame")`）后，这个名称改指向新建的窗口，旧窗口隐藏，改完的代码不必重载就能测试。
- `load` 加载的插件，如果它的 .toc 是游戏启动后才改的，结果里写明 .toc 的改动要完整重启游戏才生效（热加载照常可用）。
- Agent 让玩家在游戏里操作的提示（`say`，如「请现在拾取一件物品」）除了写进聊天框，还在屏幕上方以金色显示，停留时间按字数计算；聊天刷屏或被窗口挡住时也能看到，关闭操作通知后照常显示。
- 修复：`api_get` 查本客户端有、手册没有写的全局函数（如 `EnumerateFrames`），不再回答「不存在」；`InCombatLockdown` 等全局函数不再只给出本客户端没有的 `C_` 同名函数。

暴雪界面索引与实测记录：

- Agent 能查本客户端暴雪自带界面的结构：框体、模板、mixin、全局表与函数（如鼠标提示的 `TooltipDataProcessor`、玩家头像框体 `PlayerFrame`），以及各文件注册的事件；本客户端不加载的暴雪插件（如地下城手册 `Blizzard_EncounterJournal`）会注明。索引只记名称、定义位置和结构，不含暴雪的代码与文字；随程序自带，并随内容包更新。
- Agent 在游戏中核实过的名称按客户端版本记录下来，之后查询与检查直接使用，结论可以注明「已在游戏中实测」。
- 静态检查：暴雪界面定义的全局名称不再列为无法确认，改为一条提示，写明定义所在的文件与插件；按需加载的暴雪插件写明需先加载。游戏未运行时，实测过的名称同样可以判定。
- MCP 新增 `ui_search`、`ui_get`（暴雪界面索引）与 `api_verify`（在游戏中核实名称并记录；事件名用 `C_EventUtils.IsEventValid` 核实）；`api_search`、`api_get`、`ui_get` 的结果带 `seen`（游戏答复的类型与时间）。

给扩展作者：

- 新建的本机扩展（`new_extension`）在 `requires.workshop` 写当前这一代 `0.10.0`，不再写补丁版本：0.10.x 的无限工坊都能运行。
- 游戏部分的版本写在三处，提高时一起改：清单的 `requires.kit`、插件 `.toc` 的 `## X-Wuxian-Requires: WuxianKit 0.10.0`、Lua 第一行的 `Kit:Requires("0.10.0")`。扩展框架 0.10.0 以上按 `.toc` 判断；更早的扩展框架不读这个字段，由 Lua 第一行拦下。
- 本机扩展的最低制作版本取 `requires.kit` 与各插件 `WuxianKit` 一项中较旧的；只有带游戏部分（`addons`，或 `driver: "local"` 的应用）的本机扩展参与这项判断。
- 本机扩展行的 `game.state` 新增 `outdated`（扩展框架因版本没有加载），`player.action` 新增 `update`，`text` 与版本检查的说明相同。
- 扩展摘要（`extension_summary`）新增 `requires`，每个游戏插件新增 `requires`（它 `.toc` 里的 `X-Wuxian-Requires`）。
- MCP 新增 `extensions`、`versions_wait`；`status` 的说明补充 `update` 的各个状态、`addons_update`、`kit.outdated`，`versions.items` 只列需要处理的项，每项带 `text`。
